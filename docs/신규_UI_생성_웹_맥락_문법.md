# 신규 UI 생성용 웹 맥락 문법

## 목적

원본 화면이 없는 신규 MES UI를 만들 때 매번 비슷한 Figma 화면을 찾거나 AI가 임의로 조합하지 않게 한다. 실제 MES 웹에서 반복된 사용 방식을 페이지, 팝업, 섹션, 동작 문법으로 압축해 생성기에 제공한다.

기계 판독 원본은 `component-library/src/design-system/registry/web-generation-context.json`이다.

## 생성과 재현을 분리한다

| 요청 | 먼저 읽는 정보 | 읽지 않는 정보 |
|---|---|---|
| 신규 UI 생성 | 업무 의도, 반복된 웹 조합 문법, Context Rule, Pattern·Component 계약 | 화면별 Figma 대조 이력, 픽셀 미검증 수치 |
| 기존 화면 재현·감사 | 대상 Figma, 실제 웹 관찰값, 불일치, 검증 상태, 디자인 시스템 계약 | 없음 |

신규 생성에서 Figma는 완성 화면을 고르는 출발점이 아니다. 사용자가 참고 화면을 주거나 외형 근거가 필요할 때만 추가한다.

## 실제 웹에서 추출한 1차 문법

### 페이지

| 문법 | 근거 | 사용 맥락 |
|---|---:|---|
| 조회·그룹화·표·하단 액션 목록 | 34개 화면 | 엔티티 조회, 선택, 출력, 등록 진입 |
| 지표·차트·분석 표 | 6개 화면 | 기간·기준 변경이 지표와 결과를 함께 갱신 |
| 설비 상태 모니터링 | 1개 화면 | 설비 상태 카드와 상세·알람 진입 |
| 추적·마스터·상세 결과 | 1개 화면 | 한 조건에서 연결된 복수 결과 탐색 |

한 건만 관찰된 문법은 `single-case`다. 신규 화면의 자동 기본값으로 사용하지 않는다.

### 팝업 흐름

| 문법 | 근거 | 사용 맥락 |
|---|---:|---|
| 현재 목록을 유지하는 등록·편집 슬라이드 | 23개 흐름 | 기본정보와 상세 목록을 길게 편집 |
| 검색·선택·반환 중앙 팝업 | 4개 흐름 | 제한된 범위에서 대상을 찾아 원래 작업에 반환 |
| 중앙 선택 후 우측 등록 슬라이드 | 2개 흐름 | 지시·발주 같은 선행 대상을 선택한 뒤 등록 |
| 현재 업무 보조 분석 중앙 팝업 | 1개 흐름 | 페이지 이동 없이 일시적인 계산·비교 결과 확인 |

### 섹션 조합

- 기본정보 → 업무정보 → 상세목록: 13개 흐름
- 기본정보 → 커스텀 정보: 5개 흐름
- 기본정보 → 검사항목: 3개 흐름
- 시간표 → 가동기록 → 비가동시간: 1개 흐름

## 신규 화면 생성 순서

1. 사용자가 얻으려는 결과를 조회·등록·편집·선택·분석·모니터링으로 분류한다.
2. 전체 페이지인지 현재 페이지 위의 작업인지 정한다.
3. 페이지 또는 팝업 문법을 선택한다.
4. 업무 순서대로 섹션 문법을 조합한다.
5. 선택, 행 변경, 취소 복원, 스크롤 소유 동작을 연결한다.
6. 승인된 Pattern과 Component로 구현한다.
7. 기존 문법으로 설명되지 않는 부분만 격리 후보로 만든다.

## MCP 사용

- `mes_get_web_generation_context`: 신규 UI 생성 전 호출한다. 반복 문법과 가까운 실제 웹 예시만 반환한다.
- `mes_get_reproduction_audit_context`: 기존 화면을 재현·정규화·감사할 때만 호출한다. Figma 대조와 미검증 상태는 이 경로에만 있다.
- `mes_resolve_screen`: `intent`에 따라 두 정보가 섞이지 않도록 계약을 만든다.

신규 `ScreenRequest`에는 선택한 `webContext.pageArchetypeRef` 또는 `webContext.overlayGrammarRef`를 적고 필요한 `sectionRecipeRefs`를 순서대로 적는다. 이 선택이 없거나 target과 맞지 않으면 resolver가 구현 전에 차단한다. 신규 요청의 결과 계약에는 `webGenerationContext`가 들어가고 `reproductionAuditContext`는 `null`이어야 한다. 레지스트리와 MCP 검사가 이를 확인한다.

## 추가 관찰 방법

앞으로 웹에서 새로운 화면이나 연결 흐름을 발견하면 먼저 `web-ui-usage-inventory.json`에 사실을 기록한다. 같은 구조가 두 건 이상 확인되면 `web-generation-context.json`의 `repeated` 문법으로 승격할 수 있다. 한 건뿐이면 `single-case`로 유지한다.

이 방식으로 아직 제공되지 않은 화면도 전체 체계를 다시 흔들지 않고 누적할 수 있다.
