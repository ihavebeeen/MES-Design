# AI 작업 시행착오 및 방지 규칙

이 문서는 저장소 안팎에서 실제로 발생한 반복 실수와 재발 방지 원칙을 보존한다. 매 작업마다 전체 목록을 의식적으로 수행하는 무거운 체크리스트가 아니라, 관련 상황에서 적용할 판단 기록이다.

## 핵심 원칙

- 코드상 추론과 실제 브라우저·Figma에서 관찰한 결과를 구분해 말한다.
- 확인하지 못한 값은 추정으로 채우지 않고, 대체값을 썼다면 결과와 함께 먼저 밝힌다.
- 이미 찾은 수치·이름·경로는 구현 시 기억으로 다시 쓰지 않고 원문을 재확인한다.
- 사용자 스크린샷과 재현 로그는 에이전트의 코드 추론보다 우선하는 증거다.
- 같은 문제가 여러 곳에 있을 수 있으면 기억으로 범위를 정하지 않고 검색으로 개수를 확인한다.
- 자식 컴포넌트는 부모 레이아웃의 배치 책임을 침범하지 않는다.

## 반복된 문제와 대응

| 문제 | 실제 원인 | 대응 |
|---|---|---|
| 확인하지 않은 결과를 완료라고 보고 | 코드가 맞아 보인다는 추론을 실행 관찰과 혼동 | 확인 수단과 실제 실행 결과를 명시 |
| 일부만 수정하고 전부 수정했다고 보고 | 유사 항목의 총개수를 검색하지 않음 | `rg`로 범위를 확정하고 변경 후 다시 대조 |
| 사용자 재현보다 기존 논리를 방어 | 방금 작성한 코드의 설명이 더 쉬움 | 스크린샷·로그에서 출발해 원인을 다시 탐색 |
| 알고 있던 값을 구현 시 임의 변경 | 긴 대화에서 정확한 값과 구현 시점이 멀어짐 | 측정값을 즉시 기록하고 사용 시 원문 재확인 |
| 다른 실행 환경을 동일하게 가정 | Node, 브라우저, Figma 자동화의 세부 구현 차이 | 결과가 필요한 실제 환경에서 직접 실행 |
| 공용 SearchInput의 수직 정렬 오류 | 자식의 `self-start`가 부모 `items-center`를 덮음 | 크기는 `w-fit`·`shrink-0`, 교차축 배치는 부모가 소유 |

## Figma 외부 재현에서 발생한 사례

2026-08-05 외부 에이전트가 저장소 스펙으로 Figma 화면을 만들면서 다음 대체값을 임의 사용했다.

| 항목 | 저장소 근거 | 잘못 사용한 값 |
|---|---|---|
| 폰트 | Pretendard | Inter |
| 아이콘 | 실제 SVG path | 유니코드 기호 |
| 테이블 행 | 30px | 34px·40px |

색상과 간격처럼 바로 복사 가능한 값은 지켰지만, 별도 탐색이 필요한 폰트·아이콘은 흔한 대체값으로 채운 것이 원인이었다. 행 높이는 이미 확인했음에도 구현 시 다시 대조하지 않았다.

### Pretendard 자동화 주의

브라우저는 저장소의 `public/fonts`를 웹 폰트로 사용할 수 있지만 Figma Plugin API의 `loadFontAsync`가 같은 폰트를 사용할 수 있다는 뜻은 아니다. Figma 앱에서 사람이 선택할 수 있는 로컬 폰트와 자동화 실행 환경이 로드할 수 있는 폰트 목록도 다를 수 있다.

따라서 Figma 자동화에서 Pretendard 로드 가능 여부를 시작 시 한 번 확인한다. 불가능하면 임의로 동일하다고 표현하지 않고 대체 폰트 사용 사실과 후속 교체 필요성을 밝힌다. 구체적인 Figma 플랜별 폰트 업로드 가능 여부는 별도 확인 대상이다.

## 검증과 보고

- TypeScript·정적 검색을 통과했다고 화면을 실제로 확인했다고 말하지 않는다.
- 브라우저 렌더링, DOM 크기, overflow, 클릭·입력·취소 복원과 시각 회귀 중 실행한 항목만 검증 근거로 쓴다.
- 환경 제약으로 못 한 검증과 그 안에서도 수행한 검증을 구분한다.
- `구현됨`, `검증됨`, `배치 완료`, `전체 완료`는 [AI 완료 판정 및 보고 정책](./AI_완료_판정_및_보고_정책.md)에 따라 사용한다.

새로운 실수 유형이 반복되면 사례를 무조건 늘어놓지 않는다. 기존 원인으로 설명되지 않을 때만 이 문서에 새 유형을 추가한다.
