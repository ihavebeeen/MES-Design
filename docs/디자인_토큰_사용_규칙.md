# 디자인 토큰 사용 규칙 (1층 문서)

**목적**: 이 문서는 컴포넌트 라이브러리(2층)에 이미 코드화된 18개 컴포넌트를 전수 조사해서
"어떤 상황에 어떤 간격/색/크기를 쓰는지"를 규칙으로 뽑아낸 것이다. 색상 hex 값 자체(팔레트)는
`component-library/src/app/globals.css`가 원본이고, 이 문서는 그 팔레트를 **언제** 쓰는지에
대한 규칙만 다룬다. 최종 목표(A-to-Z 디자인 시스템에서 AI가 화면을 자동 조립하는 것)를 위한
3개 층 중 1층 — 2층(컴포넌트)은 `component-library/src/components/ui/`, 3층(합성 패턴
카탈로그)은 앞으로 `docs/화면_패턴_카탈로그.md`(가칭)에 누적 예정.

**주의**: 아래 값들은 전부 지금까지 실측/코드화된 18개 컴포넌트에서 역으로 뽑아낸 것이라
"우리가 실제로 이렇게 쓰고 있다"는 관찰 결과지, 처음부터 설계된 이상적인 스케일이 아니다.
그래서 값이 딱 떨어지게 정리되지 않는 부분도 있고, 그런 경우는 억지로 하나로 합치지 않고
그대로 기록했다. 새 컴포넌트/패턴이 추가될 때마다 이 문서도 같이 갱신해야 한다.

**시각 참고**: 색상 팔레트와 타이포그래피 스케일은 데모 페이지(`component-library`
실행 후 최상단, `page.tsx`의 Foundation 섹션)에서 실제 스와치/샘플 텍스트로도 볼 수 있다.
값이 바뀌면 이 문서, `globals.css`, `page.tsx`의 팔레트 상수(`GRAY_PALETTE` 등) 세 곳을
같이 갱신해야 한다.

## 1. 색상 — 언제 어떤 걸 쓰는가

팔레트 자체(Gray 0~140, Primary 10~110, Danger 10~110, Yellow 10/20/50만)는 `globals.css` 참고.
여기서는 역할(role)별로 어떤 단계를 쓰는지만 정리.

### 1-1. 텍스트 색
| 역할 | 토큰 | 쓰이는 곳 |
|---|---|---|
| 기본 텍스트(제목/본문 강조) | `mes-gray-130` | 모든 다이얼로그 제목, Input/Select 입력값, Table 셀, 각종 label |
| 보조 텍스트(설명/부제) | `mes-gray-90` | RadioChoiceDialog 옵션 설명, Tag(gray) |
| 플레이스홀더/힌트 | `mes-gray-60` | Input/Select placeholder, 드롭다운 hover 배경과 짝지어 쓰는 경우 많음 |
| 비활성(disabled) 텍스트 | `mes-gray-70` (일부 `mes-gray-60`) | Input/Select/Table disabled 텍스트 |
| 흰색 텍스트 | `white` | 채워진(fill) 배경 위 텍스트 전부(Button fill*, Badge blue/red, Toast, Tag) |
| 브랜드 강조 텍스트/링크 | `mes-primary-60` | Button lineMain, NoticeBanner 링크, Badge blueLight/blueOutline |
| 위험/에러 텍스트 | `mes-danger-60` | 없음(현재는 배경으로만 씀 — 위험 텍스트 색 자체는 아직 실측 사례 없음, 확인 필요) |
| 예외값(팔레트에 없음) | `#696f83`("mc/100") | ConfirmDialog description 전용 — 확정 Gray 팔레트 어느 단계와도 불일치, 임의로 편입 금지 |

### 1-2. 배경/테두리 색
| 역할 | 토큰 | 쓰이는 곳 |
|---|---|---|
| 기본 입력 테두리 | `mes-gray-30` | Input/Select 기본 테두리, 다이얼로그 헤더 하단 테두리, Table 셀 구분선(선택/신규 행) |
| 진한 강조 테두리(focus/open) | `mes-gray-130` | Input focus, Select 펼침(open) 상태 — 파란 포커스링이 아니라 진회색 테두리로 처리하는 게 이 시스템의 규칙 |
| 옅은 강조 배경(hover, 비선택) | `mes-gray-20` | Select/Combobox/Filter 목록 항목 hover, Input readonly 배경 |
| 더 옅은 배경 | `mes-gray-10` | lineBlacktxt Button hover, Table disabled 행 배경 |
| 비활성(disabled) 배경 | `mes-gray-30`~`mes-gray-40` | Input/Select/Button/Checkbox/Radio disabled 배경 — 항상 텍스트는 gray-60~70과 짝 |
| 카드/배너 옅은 배경 | `mes-gray-20` | RadioChoiceDialog 경고 배너, (예전) CenterModal 콘텐츠 영역 |
| 브랜드 기본 | `mes-primary-60` | Button fillMain, Radio/Checkbox 선택됨, Badge blue/blue2, Sidebar 2-depth 선택 항목 |
| 브랜드 hover | `mes-primary-70` | Button fillMain hover(한 단계 진하게) |
| 브랜드 옅은 배경 | `mes-primary-10`/`20` | Button lineMain hover, Badge blueLight, FilterTag 배경 |
| 선택된 리스트 항목(예외) | `#e8f0fe` | Select/Combobox 선택된 항목 배경 — 확정 Primary 11단계 중 어느 값과도 정확히 일치하지 않는 별도 값(담당자가 "그대로 유지"로 확정), 팔레트에 억지로 편입하지 않음 |
| 위험/에러 강조 | `mes-danger-60` | Button fillRed, Badge red, Toast(RED), ConfirmDialog tone="error" 아이콘 |
| 경고 강조 | `mes-yellow-50`(아이콘) / `mes-yellow-10`+`20`(배경+테두리) | NoticeBanner, ConfirmDialog tone="warning" |
| 알림/정보 강조 | `mes-primary-60` | ConfirmDialog tone="info" (브랜드색 재사용, 별도 색 없음) |
| 검정(고대비) | `mes-gray-130` | Button fillBlack, Sidebar 배경(순검정 `#000`은 gray-140), 확정 버튼(다음/저장) |

**규칙화**: 새 컴포넌트에 색을 정할 때 "이건 무슨 역할인가"부터 정하고 위 표에서 매칭되는
role을 찾는 순서로 접근한다. 표에 없는 새로운 role이 필요하면(예: 성공/success 톤) 임의로
비슷한 색을 끌어쓰지 말고 실측하거나 담당자에게 확인 후 이 표에 새 행으로 추가한다.

## 2. 간격(spacing) — 실측된 값과 상황

지금까지 나온 px 값을 오름차순으로 정리하고, 공통적으로 어떤 상황에 쓰였는지 묶었다.
Tailwind의 4px 배수 스케일과 거의 일치하지만 완전히 일치하지는 않는다(예: 5px, 9px 같은
값도 실측으로 확인된 값이라 그대로 유지).

| 값 | 주로 쓰이는 상황 |
|---|---|
| 1px | 테두리 두께(거의 전부), Radio 바깥 원 인셋 |
| 2px | Progress 트랙-라벨 gap(아주 좁은 간격) |
| 3px | Badge/Tag 세로 padding, FilterTag 우측 padding, Checkbox radius |
| 4px | Sidebar 1-depth 리스트 gap, Tag 요소간 gap, Button 기본 radius |
| 5px | 검색창 내부 아이콘-텍스트 gap(Filter/Combobox SearchBox 공통), 활성 필터 태그 박스 padding |
| 6px(`1.5`) | 아이콘-라벨처럼 "붙어있는 느낌"의 좁은 gap(RadioChoiceDialog 라디오-텍스트, PageTopTabItem 내부, 대부분의 `gap-1.5`) |
| 8px | 카드/토스트류 내부 padding(Toast `p-4`는 16이지만 아이콘-텍스트 gap은 8), NoticeBanner 경고배너 gap, Select/Combobox 패널 내부 padding |
| 10px(`2.5`) | "표준 요소간 gap" — 헤더/푸터 상하 padding, 버튼 그룹 gap, Sidebar 토글/항목 gap. 이 시스템에서 **가장 많이 재사용되는 간격** |
| 12px | Sidebar 2-depth 항목 좌우 padding, Table 관련 여백 |
| 14px | 다이얼로그 헤더 우측 padding(닫기 버튼과의 균형용, 좌측 20px과 비대칭) |
| 16px | "편안한 카드 padding" — Toast 전체 padding, RadioChoiceDialog 경고배너 상하 padding, Sidebar 하단바 padding |
| 20px | **다이얼로그 표준 간격** — 헤더/본문 좌측 padding, 본문-푸터 간격(배너 유무 무관 항상 20px로 담당자가 통일 지시), RadioChoiceDialog 본문 내부 gap. 다이얼로그류를 만들 때 기본으로 20을 먼저 고려 |
| 24px | 그림자 blur 값에서 주로 등장(간격보다는 elevation 쪽에 가까움) |
| 30px | Progress 전체 높이, RadioChoiceDialog 경고배너 좌우 padding |
| 32px | ConfirmDialog 본문 padding(상/좌우, 원래 실측값 — 담당자가 이후 하단만 0으로 조정) |

**규칙화**:
- 다이얼로그(모달) 계열을 새로 만들 때: 헤더 좌측 20px/우측 14px, 본문 좌우 20px, 본문↔푸터
  간격 20px(한쪽만 padding 책임지는 "one-sided gap" 패턴 — 아래 5번 참고)를 기본값으로 시작한다.
- 아이콘-텍스트처럼 붙어있는 두 요소는 6px(`gap-1.5`), 버튼 그룹처럼 약간 떨어진 두 요소는
  10px(`gap-2.5`)를 기본으로 쓴다.
- 5px, 9px처럼 4px 배수에서 벗어난 값은 전부 실측 근거가 있는 값이니 "이상하다"고 4px
  배수로 반올림하지 않는다.

| 38px | PageTopTabItem 행 전체 |
| 40px | Button `basic`, 다이얼로그 푸터 버튼 |
| 42px | Sidebar 1-depth 항목(즐겨찾기/대시보드 포함) |

세 가지는 이미 여러 컴포넌트에서 반복 확인된 강한 규칙이라 새 다이얼로그에도 그대로 적용한다.

## 4. Radius 스케일

| 값 | 쓰이는 곳 |
|---|---|
| 2px | Button `xsmall`, Badge, Tag |
| 3px | Input `small`, Checkbox, FilterTag |
| 4px | Button `basic`/`small`, Input `default`, Table 컨테이너, 각종 카드형 배경 |
| 8px(`rounded-lg`) | 드롭다운/플라이아웃 패널(Select/Combobox/Filter 공통), Sidebar 2-depth 항목, NoticeBanner |
| 12px | ConfirmDialog(작은 확인 팝업) |
| 16px | RadioChoiceDialog, (보류된)CenterModal — ConfirmDialog보다 "더 크고 무거운" 모달 |
| full(pill) | Progress 트랙, Toast, Sidebar 토글/뱃지형 요소 |

**규칙화**: "작은 인터랙션 요소(버튼/인풋/뱃지) = 2~4px", "떠 있는 패널(드롭다운/카드) = 8px",
"모달 = 12~16px(크기에 따라 다름, 작은 확인창 12 / 큰 폼형 모달 16)", "캡슐형 = full"이라는
4단계 규칙이 이미 일관되게 지켜지고 있다. 새 컴포넌트도 이 4단계 중 하나를 먼저 적용해보고,
실측값이 다르면 그때 교체한다.

## 5. 그림자(elevation) 스케일

| 프리셋 | 값 | 쓰이는 곳 |
|---|---|---|
| 낮은 부유(hover 패널) | `0 2px 8px rgba(0,0,0,.12)` | Select/Combobox/Filter 드롭다운 패널 |
| 중간 모달 | `0 4px 16px rgba(0,0,0,.2)` | ConfirmDialog(작은 확인창) |
| 큰/집중형 모달(오프셋 없음, 사방 확산) | `0 0 24px rgba(0,0,0,.2)` | RadioChoiceDialog, (보류된)CenterModal |
| 토스트 | `drop-shadow(0 0 12px rgba(0,0,0,.2))` | Toast |

**규칙화**: 오프셋이 있는 그림자(`0 Npx Mpx`)는 "화면 위에 얹힌 작은 패널/카드" 느낌, 오프셋
없이 사방으로 퍼지는 그림자(`0 0 Npx`)는 "화면 중앙에서 시선을 끄는 큰 모달" 느낌으로
구분해서 쓰고 있다. 새 모달의 무게감(작은 확인창인지, 화면을 크게 채우는 폼형 모달인지)에
따라 이 중 하나를 고른다. 이 부분과 관련해서도 참고: RadioChoiceDialog(16px radius +
24px 그림자)와 ConfirmDialog(12px radius + 16px 그림자)가 다른 이유는 실측상 서로 다른
독립 노드였기 때문이며, 두 값을 통일해야 하는지는 아직 담당자 확인 필요 항목으로 남아있음.

## 7. 반복되는 조합 레시피

- **디스에이블(disabled) 레시피**: 배경 gray-30~40 + 텍스트 gray-60~70 + (테두리가 있다면)
  테두리도 같은 gray 계열. Button/Input/Select/Checkbox 공통.
- **하나만 진해지는 hover 레시피**: 배경/텍스트 색은 그대로 두고 배경만 한 단계 진한 회색
  또는 진한 브랜드색으로 바뀜(Button 각 variant hover, Select/Combobox 항목 hover).
- **"간격은 한쪽만 책임진다" 레시피**: 두 블록 사이 간격을 만들 때 앞 블록의 하단
  padding과 뒷 블록의 상단 padding을 동시에 주면 간격이 두 배로 겹친다 — 그래서 이 시스템은
  항상 뒷 블록(주로 푸터)의 padding만으로 간격을 맞추고 앞 블록엔 해당 방향 padding을
  주지 않는다. ConfirmDialog(본문→푸터), (보류된)CenterModal(콘텐츠→푸터)에서 확인된 규칙 —
  다이얼로그류를 새로 만들 때 기본으로 적용.
  ⚠️ 이 규칙은 "실측값보다 담당자 지정값이 우선한다"는 사례이기도 함 — ConfirmDialog는 원래
  실측값이 52px(32+20)였지만 담당자가 20px로 명시적으로 낮춰서 최종 확정함. 즉 실측은
  출발점이지 항상 정답은 아니다.
- **비제어(uncontrolled) 지원 레시피**: `value`/`onChange`를 안 넘겨도 `defaultValue` 기준
  내부 state로 동작하게 만든다(Combobox, RadioChoiceDialog) — 제어형만 지원하면 부모가
  깜빡 안 넘겼을 때 컴포넌트가 먹통이 되는 문제가 실제로 있었음(2026-07-28).
- **아이콘 재사용 우선 원칙**: 새 UI에 필요한 아이콘이 기존 33종 실측 아이콘과 형태가
  같으면(회전만 다르거나) 새로 만들지 않고 회전/색만 바꿔 재사용한다(Sidebar 펼침
  화살표가 `IconArrow`를 회전시켜 재사용한 사례). 형태 자체가 다르면 임시로 lucide 아이콘을
  쓰고 "확인 필요" 목록에 등록해둔다.

## 8. 팔레트/스케일에 편입하지 않은 예외값 (의도적으로 안 맞춤)

이 값들은 "왜 표준 스케일과 안 맞지?"라고 나중에 임의로 고치면 안 되는, 실측 근거가
분명한 예외다.

- `#696f83`("mc/100", ConfirmDialog description) — 확정 Gray 팔레트 어느 단계와도 불일치
- `#156be9`(Toast BLUE 배경) — 확정 Primary-60(`#1573FB`)과 미묘하게 다른 값, 별도 프레임 원본값
- `#e8f0fe`(Select/Combobox 선택 항목 배경) — 확정 Primary 팔레트 어느 단계와도 불일치, 담당자가 "그대로 유지"로 확정
- `#d4eaff`(Button opacityMain hover) — 팔레트에 없는 hover 전용 값
- Toast RED 테두리 `rgba(255,108,108,.2)` / BLUE 테두리 `rgba(26,61,112,.6)` — 서로 다른 반투명값, 팔레트 토큰 아님
- Toast radius RED 30px / BLUE 84px — 값 자체는 다르지만 렌더링 결과(완전 캡슐)가 같아서 코드는 `rounded-full`로 통일
