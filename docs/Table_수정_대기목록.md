# Table 컴포넌트 — 수정 대기목록 (2026-07-28 5차 갱신)

원래 "지금은 토큰이 부족하니 기록만 해두라"는 요청으로 작성된 문서였는데, 담당자가
"수정 고고"라고 해서 2026-07-28에 1~5번을 전부 코드에 반영함. **현재 시점 기준 미해결
항목은 없음** — 새 지적이 들어오면 이 문서에 이어서 추가할 것.

관련 파일: `component-library/src/components/ui/table.tsx`,
`component-library/src/app/page.tsx`(데모), `component-library/src/components/ui/checkbox.tsx`

배경: Table을 같은 날 안에 1차(Figma 실측) → 2차(실사용 화면 피드백 5건) → 3차(재검토
피드백 4건) → 4차(문서화만) → 4차 후속(버튼 디자인 정정) → 5차(이 문서의 1·2·4·5·6번
일괄 반영)까지 진행. 상세 경위는 `AGENTS.md`의 "Table 작업 회고" 섹션 참고.

## 1. (해결됨, 5차) 체크박스는 항상 가장 왼쪽 고정, 그 오른쪽에 그룹 열기/접기

담당자 원문: "체크박스가 가장 좌측에 잇어야 하고 체크박스영역은 고정. 그 우측으로
그룹화 열기/접기가 나와야되는데"

- 원인: 헤더 행에서 depth별 마스터 토글 버튼을 체크박스보다 **왼쪽에** 렌더링하고 있었음.
- 수정: 헤더 렌더 순서를 [체크박스] → [마스터 토글 영역]으로 교체. 그룹행(`GroupHeaderRow`)
  은 원래도 [체크박스] → [펼침 아이콘+라벨] 순서라 문제 없었음.

## 2. (해결됨, 5차) 헤더 컬럼과 바디 컬럼 위치가 안 맞던 버그

담당자 원문: "합계열이랑 그냥 열이랑 위치는 맞는데 이번에는 헤더 그러니까 컬럼명이랑
열이랑 위치가 안맞아"

- 원인: 헤더에만 마스터 토글 버튼 영역이 있고 그룹행/데이터행/총계행엔 그만큼의 여백이
  없어서, 헤더의 체크박스+컬럼들이 다른 행보다 오른쪽으로 밀렸던 것(2차에서 세운 "여러
  행 종류가 새 요소를 반영할 땐 전부 같은 폭을 예약해야 한다" 원칙을 3차에서 다시 어긴
  사례 — 재발 방지 규칙 6번).
- 수정: "체크박스 → 마스터 토글 영역"을 `MASTER_TOGGLE_SLOT_WIDTH`(24px) × depth 수로
  계산되는 고정폭 블록(`masterToggleAreaWidth`)으로 취급. 헤더는 이 블록 안에 실제
  버튼을 그리고, `DataRow`/`GroupHeaderRow`/`TotalsRow`는 전부 이 폭만큼 빈 스페이서를
  렌더링하도록 prop을 추가해서 통일. `renderGroupNode`까지 이 값을 재귀로 전달함.

## 3. (해결됨, 4차 후속) 그룹 펼침 버튼 디자인을 요청 범위 밖에서 임의로 바꿨던 것

담당자가 정확한 값(22x22px, 배경 `bg-mes-gray-0`, radius 3px, 테두리
`border-mes-gray-50` inside 1px)을 줘서 그룹행 펼침 버튼과 헤더 마스터 토글 버튼 둘 다
원상 복구함. 상세는 `table.tsx` 주석 7번.

## 4. (확인 완료, 5차) 그룹 라벨 텍스트 잘림 — 코드 버그 아님으로 잠정 결론

담당자가 공유한 스크린샷에서 그룹 라벨 앞글자가 잘려 보였던 것("지시일" → "시일").
코드 구조상(`overflow-visible` + `whitespace-nowrap`) 라벨이 잘릴 이유가 없고, 담당자
본인도 좁은 화면 때문일 수 있다고 언급했던 점을 종합해 뷰포트 폭에 의한 시각적 잘림으로
결론. 넓은 화면에서 다시 재현되면 별도로 조사할 것.

## 5. (해결됨, 5차) 데모 페이지가 좁아서 테이블이 한눈에 안 보이던 문제

`component-library/src/app/page.tsx`의 Table 데모 섹션 `max-w-[1100px]` 제약을 풀어서
(`max-w-none`) 화면 전체 폭을 쓰도록 변경. 컬럼 자체가 많아서 여전히 가로 스크롤은 필요할
수 있음(컨테이너 제약으로 인한 불필요한 압박만 제거한 것).

## 6. (기능 추가 완료, 실제 적용은 보류) 컬럼 가변폭 지원

담당자 원문: "그니까지금 컬럼들이 다 절대값으로 들어간거야 설마그리고 다 가변값이면
너가 작업하기 더 편하지 않을까 싶은데."

- `TableColumn.width`를 `number | { min: number; grow?: number }` 유니온 타입으로
  확장. 숫자면 기존과 100% 동일(고정 px), 객체면 `min`px 이상 유지하며 남는 공간을
  `grow` 비율로 나눠 갖는 가변폭 컬럼이 됨. `Cell` 컴포넌트가 두 형태를 모두 처리하도록
  수정.
- **아직 안 한 것**: 실제 데모 컬럼(`productionColumns`)을 가변폭으로 바꾸는 작업은
  안 함 — 어떤 컬럼을 고정으로 유지하고 어떤 컬럼을 가변으로 바꿀지는 실제 화면 기준
  판단이 필요해서(예: 시간/단위처럼 짧은 값은 고정, 품목명처럼 긴 텍스트는 가변) 담당자
  확인 후 진행하는 게 맞다고 판단함. 필요하면 말해주면 바로 적용함.
