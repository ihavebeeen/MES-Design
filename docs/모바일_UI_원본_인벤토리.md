# 모바일 UI 원본 인벤토리

## 목적

모바일 화면을 웹 컴포넌트의 축소판으로 생성하지 않도록, 원형·화면 유형·업무 흐름·최신 변경안을 서로 다른 근거로 분리한다. AI는 이 문서와 `mobile-assets.json`을 통해 먼저 셸과 화면 성격을 선택한 뒤 컴포넌트를 조합한다.

## 근거의 역할

| 근거 | Node | 역할 |
|---|---:|---|
| MES Mobile 컴포넌트 라이브러리 | `qEAQNTqXf76bYydyupti2V / 163:8929` | 모바일 전용 토큰, 크기, 상태, variant 원형 |
| 웹 2차 수정·컴포넌트 보드 | `F4n5Zr04PAbiRjfIFQAo6v / 9808:62079` | 웹과 모바일이 공유하는 의미 계약 비교. 모바일 시각값의 근거는 아님 |
| 모바일 화면 유형 보드 | `F4n5Zr04PAbiRjfIFQAo6v / 10378:90931` | 메인화면 12종 44p, 슬라이드 팝업 13종 19p 분류 |
| 실제 화면설계서 | `F4n5Zr04PAbiRjfIFQAo6v / 9082:31842` | 실제 업무 흐름, 예외, 화면 간 이동, 최신 변경안 |

## 업무 화면 묶음

| 묶음 | 주요 화면 | 해석 |
|---|---|---|
| 홈 | 홈, 전체메뉴, 알람, 사용자설정, 로그인 | 로그인 후 퀵메뉴 2×4, 공통 하단 탭 |
| 입고·출하 | 지시 리스트, 실적 등록, 입력내역, 라벨 설정 | 웹 표를 모바일 카드 리스트와 단계형 등록 흐름으로 변환 |
| 생산 | 생산실적 리스트, 품목 선택, LOT 선택, 실적 등록, 작업자 선택 | 스캔·수량·투입품 선택이 여러 하단 팝업으로 분해됨 |
| 품질 | 기본정보, 외관검사, 중량검사, 특이사항 | 하나의 긴 폼이 아니라 Step 진행을 가진 화면군 |
| 운전일지 | 일지 리스트, 일지 작성, 가동시간 | 시간 입력과 작업시간 팝업이 분리됨 |
| 라벨 | 라벨 리스트, 신규발행, 라벨확정 | 화면은 존재하지만 Figma에 개발범위 제외 표기가 있음 |
| 정비이력 | 목록, 스캔, 검색 | 스캔 키패드와 전체화면 검색을 사용 |
| 설비점검 | 기본정보, 외관검사 | 품질검사 UI를 재사용하되 데이터 API가 다름 |

## 공통 정책

- 홈 퀵메뉴는 2열, 최대 8개 노출이며 초과 시 본문만 스크롤한다.
- 공통 하단 탭은 홈·알람·설정·전체메뉴이며 팝업에서는 숨긴다.
- 날짜 기반 목록은 현재 날짜를 기본값으로 하고 오늘 chip, 하루 단위 이전/다음 이동을 제공한다.
- 일반 화면 헤더는 뒤로가기·이전 메뉴명·YOUHOST MES를 포함한다.
- Select A는 선택 즉시 적용·닫힘, Select B는 설정 화면에서 저장 후 적용한다.
- 뒤로가기는 입력값을 임시 보존한다.
- Toast는 저장 버튼 위 28px, 2.5~3초, 중복 억제 후 최신 1개를 표시한다.
- 메모·날짜·숫자 키패드는 하단 슬라이드 팝업이다. 중앙 모달로 대체하지 않는다.

## 웹과 모바일의 차이

| 의미 | 웹 | 모바일 |
|---|---|---|
| 대량 목록 | 고밀도 Table, 필터·검색 toolbar | 카드형 리스트, 화면 또는 하단 팝업 검색 |
| 등록·편집 | 우측 SideSlidePanel 또는 중앙 Modal | 전용 상세 화면 + 하단 고정 CTA |
| 보조 선택 | Select/중앙 조회 팝업 | 즉시 적용 dropdown 또는 Bottom Sheet |
| 긴 품질 폼 | 섹션을 한 화면에 조합 | Step으로 기본정보·외관·중량·특이사항 분리 |
| 탐색 | 좌측 SNB·상단 탭 | 하단 탭·뒤로가기·퀵메뉴 |
| 시스템 여백 | 브라우저 viewport | Status Bar 47px + Home Indicator 30px 포함 |

같은 업무 개념과 검증 규칙은 공유할 수 있지만 렌더링 컴포넌트와 조합 셸은 공유한다고 가정하지 않는다.

## 원본 충돌·예외 장부

- `source-error`: 출하 섹션의 일부 프레임명이 입고 화면명으로 남아 있다. 섹션과 실제 내용으로 판정한다.
- `intentional-exception`: 라벨생성은 화면이 있으나 개발범위 제외 표기가 있어 생성 표준에서 격리한다.
- `intentional-exception`: 실적 LOT 모바일은 미진행 결정이 명시되어 활성 화면에서 제외한다.
- `normalization-candidate`: 수량입력은 최신 변경안 `19649:98481`을 이전 화면보다 우선한다.
- 웹 컴포넌트 보드 `9808:62079`는 Mobile Button/Header 등의 시각값 근거가 아니다.

## 현재 상태

### 검증 판정 방식

대표 화면은 아래 세 계층을 별도로 판정한다. 한 계층이 통과했다고 화면 전체를 완료로 표현하지 않는다.

| 계층 | 검증 대상 | 현재 자동 기준 |
|---|---|---|
| 1. 구조 | 위치·크기·간격·색상·radius·핵심 typography | 375×812 CSS 좌표, 브라우저 subpixel 반올림을 고려한 0.5 CSS px 허용, 가로 overflow 0 |
| 2. 렌더링 | 텍스트 glyph와 SVG를 포함한 실제 픽셀 | Figma 2× PNG와 Chromium `deviceScaleFactor: 2` 직접 비교, 색상 threshold 0.2, diff pixel 1% 이하 승인 |
| 3. 동작 | 클릭·입력·선택·저장·취소 복원 | 레지스트리에 선언된 동작을 모두 실행하고 최종 상태를 assertion으로 확인 |

`mobile-verification-contracts.json`이 좌표, 스타일, 2× snapshot, 동작 ID와 계층별 상태를 소유한다. `mobile-assets.json`의 화면 상태는 이 계약을 참조하며, 구조·렌더링·동작 중 하나라도 미승인이면 `implemented-reviewing`을 유지한다.

- 모바일 상단 탭과 네 분류 페이지: 구현됨
- 모바일 원형 컴포넌트 데모: 구현됨, 개별 원본 시각 회귀 진행 중
- 화면 유형 장부: 구현됨
- 대표 원본 화면 `홈(10378:91938)`: 구조·2× 렌더링·퀵메뉴 선택 계약을 모두 통과해 `verified`다.
- 대표 원본 화면 `입고지시 리스트(10378:91889)`: 구조·2× 렌더링·목록 선택 계약을 모두 통과해 `verified`다. 과거 1× 축소 비교의 1.1603%는 배율 혼용 결과이므로 최신 판정에 사용하지 않는다.
- 대표 원본 화면 `생산실적 등록(10378:91789)`: 구조와 입력·완료 체크 동작은 검증됐다. 2× 직접 비교가 1.6470%로 승인선 1%를 넘으므로 전체 상태는 `implemented-reviewing`이다.
- 원본 화면 `전체메뉴(10378:92070)`: 1depth 120px/2depth 255px 구조, 2× 렌더링, 메뉴 전환 동작을 모두 통과해 `verified`다.
- 원본 화면 `성적서 외관검사(10378:92529)`: 구조·2× 렌더링·일괄 선택·초기화·개별 O→△ 판정 계약을 모두 통과해 `verified`다.
- 원본 화면 `일지작성(10378:91977)`: 구조와 근무조 선택·입력·저장·취소 복원은 검증됐다. 2× 직접 비교가 1.1802%로 승인선 1%를 넘으므로 전체 상태는 `implemented-reviewing`이다.
- 원본 화면 `입고실적 등록(10378:91516)`: 파란 헤더 116px 겹침, 표 헤더 40px, 첫 행 54px·후속 행 44px, 고정 액션 구조와 수량 입력·완료 체크 동작은 검증됐다. 2× 직접 비교가 1.3942%로 승인선 1%를 넘으므로 전체 상태는 `implemented-reviewing`이다.
- 원본 화면 `정비 등록(10378:93359)`: 날짜 스트립, 168px/126px 섹션, 48px 메모 행, Select 선택·시간 입력·메모 열기 동작은 검증됐다. 2× 직접 비교가 1.1940%로 승인선 1%를 넘으므로 전체 상태는 `implemented-reviewing`이다.
- 원본 화면 `성적서 중량검사(10378:92711)`: 12px Cavity 컨테이너, 319×262 셀 그리드, 4px 셀 간격, 하단 입력 영역과 배열 방식·Cavity·값 입력 동작은 검증됐다. 2× 직접 비교가 1.1989%로 승인선 1%를 넘으므로 전체 상태는 `implemented-reviewing`이다.
- 계층 검증 계약은 현재 대표 9종에 연결됐다. 9종 모두 구조·동작 계층은 통과했으며 렌더링 계층은 4종 `verified`, 5종 `reviewing`이다.
- 인벤토리에 등록된 대표 원본 프레임 35개 코드화: 완료. 메인 19개·팝업 16개 모두 개별 `/visual-regression/mobile-source/{asset}` 경로와 실제 Figma export 기준 이미지를 갖는다.
- 이번에 추가한 26개는 viewport 375×812, 가로 overflow 0, 핵심 입력·선택 상호작용과 최대 6% 회귀선(BOM 선택만 7%)을 통과하는 `implemented-reviewing` 상태다. 1%를 넘으므로 `verified`로 승격하지 않는다.
- 화면 유형 보드의 44개 메인 페이지·19개 팝업 페이지는 대표 프레임과 반복 변형을 합친 수량이다. 대표 프레임 코드화 완료를 63개 페이지 전체 픽셀 승인으로 표현하지 않는다.

### 2026-08-20 대표 프레임 재대조에서 확인한 재발 원인

- 입고 목록의 그라데이션을 화면 y=0에서 시작해 원본 y=47보다 위로 배치한 구현 오류가 있었다. 상태바는 단색이고 그라데이션은 상태바 아래에서 시작하도록 분리했다.
- 하단 탭 아이콘을 모두 24×24로 늘리면서 원본 SVG의 내부 도형 크기와 알람 아이콘 하단 획이 손실됐다. 24px 슬롯과 실제 SVG 크기를 분리했다.
- 생산실적 화면에 원본에 없는 하단 구분선·Home Indicator가 있었고 업무 바로가기에는 Lucide 대체 아이콘이 사용됐다. 원본 프레임 구조와 SVG로 교체했다.
- `mobile-figma-*.png` 회귀 기준은 실제 Figma export임을 해시·픽셀 비교로 재확인했다. 스냅샷 갱신으로 차이를 숨기지 않고 화면 코드를 기준에 맞춘다.
- 입고실적은 날짜 카드 좌표만 맞춘 채 파란 배경을 99px에서 잘라 원본의 116px 겹침을 놓쳤고, 첫 데이터 행을 후속 행과 같은 44px로 처리해 이후 모든 행이 10px 위로 밀렸다. 헤더 높이와 첫 행/반복 행을 별도 구조 계약으로 분리했다.
- 중량검사는 Cavity 외곽 박스만 계약에 넣어 내부 구분선, 10×10 셀의 4px 간격·회색 범위, 60px 라벨과 94.5px 입력 폭 차이를 잡지 못했다. 헤더·셀 그리드·값 입력 행을 별도 구조 계약으로 확장했다.
