# MES 디자인 시스템 규칙

이 문서는 신규 UI 생성과 기존 UI 감사에서 공통으로 적용하는 현재 규칙이다. 개별 컴포넌트 API는 [컴포넌트 문서](./components/README.md), 기계 판독 데이터는 `asset-manifest.json`을 사용한다.

## 1. 구성 단계

| 단계 | 역할 | 예시 |
|---|---|---|
| Foundation | 색상, 글꼴, 간격, radius, shadow, 아이콘 | semantic token, icon |
| Component | 독립적인 UI 기능과 상태 | Button, Input, Checkbox |
| Section | 한 업무 영역의 제목, 경계, 입력·목록 조합 | SectionFrame, FormGrid |
| Pattern | 반복되는 업무 해결 방식과 동작 | 검색+테이블, 선택 행 편집 |
| Shell | 화면의 외곽 구조와 스크롤 책임 | CenterModal, SideSlidePanel |
| Screen | Shell과 Section·Pattern을 순서대로 조합한 결과 | 입고등록, 투입정보 |

화면은 컴포넌트를 임의 배치해서 만들지 않는다. 먼저 Shell을 정하고 Section 순서, Behavior, ActionSet을 선택한 뒤 필요한 Component를 채운다.

## 2. 근거 우선순위

1. 사용자가 확정한 명시적 정책
2. 승인된 레지스트리와 사용 계약
3. 반복 확인된 MES 화면 조합
4. 대상 Figma 원본의 콘텐츠·위계·상태·측정값
5. 실제 개발 웹의 연결 구조
6. 단일 화면에서만 발견된 값

단일 Figma 값이나 실제 웹의 구현 오류를 공통 규칙으로 자동 승격하지 않는다.

## 3. 자산 선택

다음 질문을 순서대로 확인한다.

1. 사용자가 이루려는 업무 결과는 무엇인가?
2. 페이지, 중앙 모달, 우측 슬라이드, 확인창 중 어떤 Shell이 맞는가?
3. 기존 Section·Pattern으로 표현할 수 있는가?
4. 어떤 Component의 의미와 상태가 필요한가?
5. 기존 자산으로 부족한 차이가 반복 가능한가?

판정은 `reuse`, `compose`, `extend`, `propose-new`, `normalize` 중 하나로 남긴다. 한 화면에서만 필요한 장식과 문구는 새 컴포넌트 근거가 아니다.

## 4. 의미 규칙

- Button은 저장·조회·삭제처럼 현재 맥락에서 실행되는 동작에 사용한다.
- Link는 화면 이동이나 상세 열기에 사용한다. 링크를 Badge로 표현하지 않는다.
- Badge와 Tag는 상태·분류를 표시하며 이동이나 실행 의미를 갖지 않는다.
- SearchInput은 현재 목록의 자유 검색어 입력이다. 구조화된 조건 추가는 Filter를 사용한다.
- Select는 제한된 값 중 하나를 선택할 때 사용한다. 여러 옵션을 한눈에 비교해야 하면 Radio를 검토한다.
- Checkbox는 복수 선택과 독립적인 참·거짓에 사용한다. 테이블 선택은 미선택 grayCheck, 선택 black을 기본으로 한다.
- Table은 열 정렬과 행 비교가 중요한 데이터에만 사용한다. 독립적인 입력 행 정렬을 위해 사용하지 않는다.

## 5. 팝업과 섹션

- CenterModal은 현재 맥락을 차단하고 짧은 조회·선택·편집을 중앙에서 끝낼 때 사용한다.
- SideSlidePanel은 목록 맥락을 유지하며 긴 등록·편집을 우측에서 이어갈 때 사용한다.
- ConfirmDialog는 짧은 확인·경고에 사용한다.
- 모달 헤더는 팝업 전체의 제목이며 모든 팝업에 필요하다.
- SectionHeader는 복수 섹션을 구분할 때만 사용한다. 섹션이 하나라면 불필요한 위계를 만들지 않는다.
- SectionFrame이 padding, divider, background를 소유한다. Shell의 높이와 스크롤을 소유하지 않는다.
- 팝업 본문만 스크롤하며 헤더와 푸터는 고정한다. 예외는 화면 계약에 명시한다.
- 취소, X, Esc, 허용된 backdrop 닫기는 같은 dismiss 경로를 사용하고 미저장 변경을 복원한다.

## 6. 테이블

- header, group, row, totals는 선택 열과 컬럼 폭 배열을 공유한다.
- 새 헤더 전용 요소를 추가하면 모든 행 종류에 같은 폭의 슬롯을 예약한다.
- 선택 상태, 활성 상태, 편집 상태를 서로 다른 행 index에 하드코딩하지 않는다.
- 선택 행에서만 Input·Select가 나타나면 선택 ID에서 편집 상태를 파생한다.
- 가로 스크롤은 데이터 폭상 필요한 경우에만 화면 계약으로 허용한다.
- 필수 고정 열은 표시 여부와 순서 변경을 비활성화하고 그 이유를 표시한다.

## 7. 디자인 값

- 색상은 의미 토큰을 우선 사용한다.
- 반복되지 않는 Figma 예외값은 근거와 함께 컴포넌트 내부에 유지하고 전역 토큰으로 만들지 않는다.
- 3px, 9px, 13px처럼 고립된 값은 자동 반올림하지 않는다.
- 유사 화면 사이의 차이는 `source-error`, `implementation-error`, `intentional-exception`, `normalization-candidate`로 분류한다.
- 정규화는 원본 콘텐츠·위계·동작을 바꾸지 않는 범위에서만 수행한다.

## 8. 동작과 접근성

- 제어 컴포넌트에 `value`를 주면 `onChange` 또는 `readOnly`를 함께 제공한다.
- no-op handler는 구현으로 인정하지 않는다.
- 키보드 포커스, Enter·Space 선택, Esc 닫기와 적절한 ARIA 이름을 유지한다.
- 아이콘만 있는 버튼은 접근 가능한 이름이 필요하다.
- 색상만으로 상태를 구분하지 않고 텍스트 또는 아이콘 의미를 함께 제공한다.
- disabled는 시각 스타일뿐 아니라 실제 비활성 속성과 연결한다.

## 9. 신규 자산 등록

새 자산은 다음 조건을 모두 만족해야 한다.

1. 기존 자산 조합으로 표현할 수 없는 이유가 있다.
2. 업무 의미가 독립적이다.
3. 두 화면 이상에서 반복되거나 반복 가능성이 명확하다.
4. 상태와 접근성 계약을 정의할 수 있다.
5. 사용자 승인을 받았다.

승인 전에는 생성 시안 또는 proposal로 격리한다. 승인 후 `components.json` 또는 `patterns.json`, 사용 계약, 문서, 테스트를 같은 변경에서 갱신한다.

## 10. 신규 UI 선택 규칙의 범위

> **핵심 선택 규칙을 기본으로 적용하고, 생성 피드백을 통해 필요한 규칙만 추가 보강**

- `component-usage-contracts.json`은 모든 컴포넌트의 실제 사용처를 전수 기록하는 파일이 아니다.
- Badge와 Link, 중앙 모달과 우측 슬라이드처럼 신규 UI의 자산 선택을 실제로 바꾸는 규칙만 둔다.
- 선택 규칙이 없는 단순 컴포넌트는 구현 소스에서 생성한 API·상태 문서만 유지한다.
- 실제 MES 웹은 사용 위치와 연결 흐름을 이해하는 참고 자료이며 표준 원본으로 자동 승격하지 않는다.
- 한 화면에서만 관찰된 차이는 공통 규칙이 아니라 관찰 또는 예외로 남긴다.
- 서로 다른 화면에서 반복되거나, 사용자가 공통 규칙으로 확정하거나, 공식 Figma 공통 명세가 있을 때만 전역 선택 규칙으로 승격한다.
- 신규 UI의 선택·배치·동작 피드백은 `generation-selection-feedback.json`에 기록하고 필요한 계약만 보강한다.

## 11. 검증 기준

- 레지스트리와 구현 파일이 일치한다.
- 공개 자산은 카탈로그와 컴포넌트 문서에서 찾을 수 있다.
- 상태·Tier·배지가 하나의 원장에서 파생된다.
- 구조적 오차는 DOM 크기와 overflow로 확인한다.
- 텍스트·SVG 렌더링 차이는 시각 회귀로 확인한다.
- 클릭·입력·선택·닫기·복원은 Playwright 상호작용으로 확인한다.
- 전체 검증 결과는 `npm run verify:full`이 자동 기록한다.

## 12. AI 생성 금지 사항

- 화면 코드에서 원시 상호작용 요소를 직접 생성하지 않는다.
- Figma Make나 일반 SaaS 관례의 설명 박스·회색 섹션 헤더를 근거 없이 추가하지 않는다.
- 비슷하게 생겼다는 이유만으로 Link, Badge, Button의 의미를 바꾸지 않는다.
- Experimental, 폐기 파일, 과거 체크리스트 숫자를 생성 근거로 사용하지 않는다.
- 검증되지 않은 화면을 정식 패턴으로 자동 승격하지 않는다.
