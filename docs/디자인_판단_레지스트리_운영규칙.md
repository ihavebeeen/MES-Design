# 디자인 판단 레지스트리 운영 규칙

## 목적

Figma와 기존 코드에서 관찰한 값을 곧바로 MES 표준으로 간주하지 않고, 반복 근거와 사용 맥락을 검토한 뒤 표준 토큰·컴포넌트·패턴으로 확정하기 위한 절차입니다.

자동 감사는 후보를 찾고 사람의 판단을 돕습니다. 자동 감사 결과만으로 코드를 일괄 수정하거나 새로운 variant를 만들지 않습니다.

## 세 계층

| 계층 | 위치 | 역할 | arbitrary 값 처리 |
|---|---|---|---|
| canonical | `src/components/ui` | 표준 컴포넌트 계약 | 가장 엄격하게 검토 |
| pattern | `src/components/patterns` | 표준 컴포넌트의 반복 조합 | 패턴 고유값인지 검토 |
| evidence | `exact-*`, 원본 화면·팝업 | Figma 원본 증거 보존 | 존재만으로 오류 처리하지 않음 |

원본 증거층의 3px을 표준 컴포넌트의 3px prop으로 자동 전파하지 않습니다. 다른 화면과 토큰 분포를 비교해 표준값을 별도로 결정합니다.

## 판단 필드

| 필드 | 의미 |
|---|---|
| `observedValue` | Figma 또는 기존 코드에서 실제 관찰한 값 |
| `canonicalValue` | MES 디자인 시스템에서 채택할 표준값 |
| `decision` | `keep`, `normalize`, `needs-review` |
| `status` | `confirmed`, `proposed`, `open` |
| `evidence` | 반복 횟수, 관련 화면·컴포넌트, Figma node와 판단 이유 |
| `scope` | 전역, 컴포넌트, 패턴, 팝업 또는 화면 예외 범위 |

### decision 의미

- `keep`: 관찰값을 표준값으로 유지합니다.
- `normalize`: 원본 증거는 보존하지만 표준 자산에서는 다른 canonicalValue를 사용합니다.
- `needs-review`: 의도와 반복 근거가 부족해 확정하지 않습니다.

## 검토 절차

1. `npm run audit:design-values`를 실행합니다.
2. `docs/디자인_값_자동감사_보고서.md`의 단발성 값 대기열을 확인합니다.
3. 동일 컴포넌트의 다른 인스턴스, 인접 화면, 토큰 스케일과 Figma 근거를 확인합니다.
4. 의도가 확인되면 `keep`, 다수 규칙과 충돌하면 `normalize`, 근거가 부족하면 `needs-review`로 기록합니다.
5. 확정된 판단만 토큰·컴포넌트·패턴 코드에 반영합니다.
6. 시각 회귀와 상호작용 검증 후 감사 결과를 다시 생성합니다.

## 판단 기준

다음 조건이 많을수록 정규화 가능성이 높습니다.

- 동일 맥락에서 한두 번만 나타나는 값
- 기존 spacing, radius, typography 스케일에 없는 값
- 동일 컴포넌트의 다른 인스턴스와 충돌하는 값
- 화면 구조나 콘텐츠 밀도로 설명되지 않는 차이
- Figma Description이나 별도 variant로 의도가 기록되지 않은 값

다음 조건이 확인되면 예외 또는 variant로 유지할 수 있습니다.

- 서로 다른 크기·상태·밀도에 따른 명확한 역할 차이
- 광학적 정렬처럼 수치만으로 대체할 수 없는 시각 보정
- Figma component property 또는 Description에 명시된 의도
- 여러 화면에서 같은 맥락으로 반복되는 값

## 예시

```json
{
  "id": "spacing.filter-toolbar-padding",
  "category": "spacing",
  "property": "padding",
  "observedValue": "3px",
  "canonicalValue": "4px",
  "decision": "normalize",
  "status": "confirmed",
  "scope": ["component:filter-toolbar"],
  "evidence": "동일 구조 18개 화면은 4px이며 3px 사용 화면에는 별도 의도나 variant가 없음"
}
```

원본 화면 재현에는 3px이 남을 수 있지만, 공용 FilterToolbar와 이후 생성 화면은 4px을 사용합니다.

## 자동 검사

- `npm run audit:design-values`: 코드의 디자인 값 분포와 후보를 JSON·Markdown으로 갱신
- `npm run check:design-values`: 코드와 커밋된 감사 결과가 일치하는지 검사
- `npm run check:design-system`: 컴포넌트 재사용, 레지스트리 무결성, 디자인 값 drift를 함께 검사

감사 결과가 달라졌다는 이유로 무조건 재생성해 통과시키지 않습니다. 새 후보가 생긴 원인을 먼저 확인하고 필요한 판단을 `design-decisions.json`에 기록합니다.
