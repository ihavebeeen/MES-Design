# MES 화면 자동화 작업 정리

> 기준일: 2026-08-24 · 현재 상태: 진행 중

## 우리가 하려는 일

사용자가 AI에게 “입고 등록 화면을 만들어줘”라고 요청하면, AI가 우리 MES에서 사용하던 디자인과 화면 구성 방식을 따라 결과를 만들게 하는 것이 목표다.

새 화면을 빠르게 만드는 것뿐 아니라, 기존 Figma나 실제 MES 화면이 공통 기준과 다르게 만들어진 경우도 찾아낼 수 있어야 한다.

## 처음에는 무엇을 했나

우선 기존 Figma 화면을 코드로 옮기고, 화면에서 반복해서 사용하는 버튼, 입력창, 체크박스, 테이블과 팝업 등을 공용으로 만들었다.

그런데 공용 부품을 사용했다고 해서 결과가 우리 MES답게 만들어지는 것은 아니었다. AI가 다음과 같은 실수를 반복했다.

- 기존 MES에 없던 회색 박스나 안내 문구를 추가함
- 중앙 팝업과 우측 슬라이드 팝업을 잘못 선택함
- 링크를 배지로 표현함
- 단순 입력 영역을 테이블로 만듦
- 섹션 순서, 간격, 스크롤과 하단 버튼 배치를 임의로 정함
- 체크박스, 숫자 입력, 취소 버튼이 실제로 동작하지 않음

결국 버튼과 입력창을 만들어두는 것만으로는 부족했다. 각각을 언제 사용하고, 여러 요소를 어떤 순서로 조합해야 하는지까지 정리할 필요가 있었다.

## 그래서 무엇을 했나

| 필요했던 것 | 진행한 작업 | 결과 |
|---|---|---|
| 기존 디자인을 확인할 기준 | 주요 화면과 팝업을 코드로 옮기고 원본 확인 경로를 만듦 | 원본 화면과 AI 시안을 구분해서 확인 가능 |
| 반복해서 쓰는 화면 요소 | 버튼, 입력창, 선택창, 체크박스, 테이블, 팝업 등을 공용으로 만듦 | 공용 화면 요소 88개 정리 |
| 화면 구성 방식 | 팝업 외곽, 내부 섹션, 테이블, 편집 목록과 하단 버튼을 분리함 | 반복 가능한 구성 방식 62개 정리 |
| 올바른 요소 선택 | 각 요소를 써야 하는 경우와 쓰지 말아야 하는 경우를 기록함 | 자주 사용하는 요소 20개의 기준 마련 |
| 올바른 배치와 동작 | 섹션 순서, 스크롤, 선택, 입력, 취소와 저장 방식을 기록함 | 자주 사용하는 구성 10개의 기준 마련 |
| AI의 임의 판단 방지 | AI가 무엇을 선택했고 다른 후보를 왜 제외했는지 남기게 함 | 잘못된 선택을 확인 가능 |
| 잘못된 구현 차단 | 팝업 종류, 섹션 순서, 하단 버튼과 실제 동작을 자동 검사함 | 주요 구조 오류를 코드 단계에서 발견 가능 |
| 다른 환경에서도 같은 결과 | 저장소 안에 AI용 안내와 실행 도구를 함께 넣음 | 다른 PC에서도 같은 기준으로 작업 가능 |

## 지금 어느 정도까지 되었나

현재 우선 세 가지 화면 구성을 같은 방식으로 반복 생성할 수 있게 만들었다.

1. 우측에서 열리는 등록 팝업
2. 화면 중앙에서 열리는 검색·선택 팝업
3. 검색 조건과 테이블이 있는 전체 페이지

앞의 두 가지는 현재 기준으로 바로 사용할 수 있다. 전체 페이지 방식은 페이지 이동 부분과 실제 원본 화면 비교가 더 필요하다.

자동 검사, 코드 오류 검사, 다른 PC에서 사용하는 연결 방식과 실제 빌드는 모두 정상 동작하는 것을 확인했다.

## 지금 할 수 있는 것

- 같은 요구와 같은 버전의 저장소를 사용하면 같은 화면 구조를 만든다.
- 기존 MES와 비슷한 화면을 찾아 그 화면의 구성 방식을 우선 사용한다.
- 팝업 종류와 내부 섹션 순서를 임의로 바꾸는 일을 줄인다.
- 공용 요소를 사용하지 않고 화면 안에서 버튼이나 입력창을 새로 만드는 일을 막는다.
- 취소, 닫기, 선택, 입력과 같은 기본 동작 누락을 검사한다.
- 회사 PC와 집 PC에서 같은 저장소를 내려받아 같은 방식으로 작업할 수 있다.

## 아직 되지 않은 것

- 모든 MES 화면이 자동 생성되는 것은 아니다.
- 현재 정교하게 정리된 대표 화면은 세 종류다.
- 등록된 모든 화면 요소의 사용 기준이 같은 수준으로 작성된 것은 아니다.
- 코드 구조가 같아도 Figma와 픽셀까지 완전히 같다는 뜻은 아니다.
- 기존 Figma와 실제 MES 중 어느 쪽이 잘못됐는지 모든 화면에서 판정한 상태는 아니다.
- 모바일은 디자인이 변경될 가능성이 있어 현재 작업을 멈추고 자료만 보존하고 있다.

## 앞으로 무엇을 해야 하나

### 1. 현재 만든 세 가지 방식부터 정확하게 검증

중앙 검색 팝업과 전체 페이지를 실제 Figma와 비교한다. 크기와 간격뿐 아니라 검색, 필터, 선택, 취소, 닫기와 스크롤도 직접 확인한다.

### 2. 실제로 필요한 화면부터 범위 확대

남은 화면을 한꺼번에 정리하지 않는다. 새 화면을 만들거나 기존 화면을 수정할 일이 생길 때, 가장 비슷한 기존 화면을 기준으로 필요한 규칙을 추가한다.

### 3. 새로운 화면 구성이 정말 필요한지 확인

기존 방식으로 표현할 수 없다고 바로 새로운 구성을 만들지 않는다. 먼저 기존 방식이 부족한지 확인하고, 실제 업무와 동작이 다른 경우에만 새로운 기준을 제안한다.

### 4. 기존 MES 화면 검사

새 화면을 검사하는 기준을 기존 화면에도 적용한다. Figma와 실제 구현의 차이를 찾아 다음처럼 구분한다.

- Figma가 잘못된 경우
- 실제 구현이 잘못된 경우
- 의도적으로 다르게 만든 경우
- 공통 기준에 맞춰 정리해야 하는 경우

## 앞으로 화면 하나를 만드는 순서

```text
업무 요구 또는 Figma 확인
→ 가장 비슷한 기존 MES 화면 찾기
→ 사용할 화면 요소와 배치 방식 결정
→ 화면 생성
→ 버튼·입력·선택·스크롤 동작 확인
→ Figma와 화면 비교
→ 사용자 확인 후 저장소에 반영
```

## 결론

지금은 AI가 화면 요소를 마음대로 조립하던 단계에서 벗어나, 기존 MES에서 사용하던 화면 구성과 동작을 먼저 확인하도록 만든 상태다.

다음에는 새로운 화면 수를 늘리기보다, 현재 만들어둔 세 가지 방식을 실제 원본과 정확히 비교하고 부족한 부분을 고치는 것이 우선이다. 이후 실제 업무 요청이 들어오는 순서대로 적용 범위를 넓힌다.
