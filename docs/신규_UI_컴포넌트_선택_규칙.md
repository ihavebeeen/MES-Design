# 신규 UI 컴포넌트 선택 규칙

> **핵심 선택 규칙을 기본으로 적용하고, 생성 피드백을 통해 필요한 규칙만 추가 보강**

## 목적

88개 컴포넌트의 모든 사용 장면을 미리 조사하지 않는다. 신규 UI에서 서로 혼동하기 쉬운 자산의 선택 기준만 관리하고, 실제 생성 오류가 생긴 부분을 누적해서 교정한다.

## 관리 범위

| 구분 | 관리 방식 |
|---|---|
| 선택에 영향을 주는 컴포넌트 | 사용·금지·대안 규칙을 생성기에 제공 |
| 단순 컴포넌트 | 실제 코드의 Props·상태·접근성 문서만 유지 |
| 실제 MES 웹 | 사용 위치와 흐름을 이해하는 참고 자료 |
| 단일 화면 관찰 | 전역 규칙으로 승격하지 않음 |

현재 선택 규칙은 `component-usage-contracts.json`, 생성 피드백 기록은 `generation-selection-feedback.json`이 기계 판독 원본이다.

## 신규 UI 생성 후 처리

1. 생성 결과의 선택·배치·동작 피드백을 확인한다.
2. 보강할 규칙이 없으면 새로운 사용처 문서를 만들지 않는다.
3. 피드백이 있으면 선택한 자산, 기대 자산과 이유를 생성 피드백 원장에 기록한다.
4. 기존 선택 규칙으로 이미 설명되면 구현만 수정한다.
5. 기존 규칙으로 설명되지 않고 반복 또는 명시적 승인 근거가 있을 때만 선택 규칙을 보강한다.

## 공통 규칙 승격 조건

다음 중 하나가 있어야 한다.

- 서로 다른 화면에서 같은 의미의 사용이 두 번 이상 반복된다.
- 사용자가 MES 공통 규칙으로 명시적으로 확정한다.
- 공식 Figma 컴포넌트 또는 공통 명세에서 계약이 확인된다.

개발 MES 한 화면에서 발견됐다는 사실만으로는 충분하지 않다. 개발 구현 오류일 수 있으므로 참고 근거로만 남긴다.

## 생성기 적용 수준

- 패턴 또는 셸 계약의 구조 위반은 기존 blocker 정책을 따른다.
- 컴포넌트의 허용 부모 목록은 아직 전수 사용처가 아니므로 불일치를 warning으로 보고한다.
- 선택 규칙이 없는 컴포넌트는 `source-api-only`로 표시하고 AI 선택을 임의로 제한하지 않는다.
