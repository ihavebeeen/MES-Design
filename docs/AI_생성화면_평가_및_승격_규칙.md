# AI 생성 화면 평가 및 승격 규칙

AI가 만든 화면은 곧바로 디자인 시스템의 표준 화면이나 재사용 패턴이 되지 않는다. 생성 결과는 먼저 Git에서 제외된 **로컬 임시 생성** 단계에 들어가며, 사용자가 보존을 요청한 결과만 Git 검토 후보가 된다. 사용자 검토와 검증을 통과한 결과만 표준 레지스트리로 승격한다.

패턴의 계층, 조합 단위와 판정 권한은 [AI UI 조합 문법 공통 정책](./AI_UI_조합_문법_공통정책.md)을 따른다. 현재 화면 레지스트리는 복수 `patternRefs` 이관을 완료했으며, 생성 화면도 승인 시 동일한 구조로 등록한다.

## 독립된 세 가지 상태

Git 저장 여부와 AI 사용 권한을 하나의 상태로 합치지 않는다.

| 축 | 값 | 의미 |
|---|---|---|
| `persistence` | `local` / `git` | 현재 PC에만 있는지, 저장소에 보존되는지 |
| `reviewStatus` | `draft` / `review` / `approved` / `rejected` / `archived` | 사용자 검토 단계 |
| `generationInfluence` | `blocked` / `reference` / `standard` | 이후 AI 생성 근거로 사용할 수 있는 범위 |

정식 단계 정의는 `generated-screen-lifecycle.json`이 관리한다. Git에 들어간 검토·반려·보관 화면도 `generationInfluence: blocked`이면 AI 생성 근거가 아니다.

## 검토 상태

| 상태 | 의미 | 이후 AI 생성에 사용 |
|---|---|---|
| `partial-success` | 일부 요구는 충족했지만 수정 또는 재검토가 필요 | 금지 |
| `review` | 자동 검증을 마치고 사용자 검토 대기 | 금지 |
| `approved` | 사용자 검토와 승격 기준 통과 | 허용 |
| `rejected` | 방향 또는 품질이 부적합 | 금지 |
| `archived` | 더 나은 후속안으로 대체된 과거 시안 | 금지 |

## 격리 원칙

- 일반 생성 결과는 `.mes-ui-preview/`, `src/generated-previews/`, `src/app/preview/`에 두며 모두 Git에서 제외한다.
- 생성 명령은 내부 QA 미리보기와 최종 파일 검사 기록만 생성하며, 미검증 결과를 로컬 인덱스에 자동 등록하지 않는다. 기존 `public/.mes-ui-preview/index.json`은 과거 초안 목록으로 보존되며 검증 통과 근거가 아니다. 사용자 전달 전 MES 규칙에 따른 렌더링·동작 확인과 `screen:handoff`가 필요하다. 원본 재현·정규화는 원본도 대조한다. 짧은 확인은 자동 저장하고 동일 렌더링은 재사용하며, 매번 캡처/장문 기록을 만들지 않는다. [전달 검사](../.agents/skills/generate-mes-ui/references/delivery-gate.md) 참고.
- `approved`가 아닌 화면은 `patterns.json`, `screens.json`, `source-assets.json`에 등록하지 않는다.
- Git 검토 후보의 코드와 평가는 추적 경로와 `generated-screen-evaluations.json`에서 함께 관리한다.
- 시각 회귀 테스트는 실패 상태를 보존하고 비교하기 위해 유지할 수 있지만, 테스트 통과 자체를 표준 승격으로 해석하지 않는다.
- 새 생성 화면이 승인되면 이전 시안은 `archived`로 바꾸거나 삭제한다.
- AI는 `influence: quarantined` 후보를 다음 화면의 디자인 근거로 사용하면 안 된다.
- 등록된 컴포넌트로만 만들었더라도 조합 근거가 없거나 미승인 패턴을 포함하면 격리한다.
- AI가 제안한 신규 패턴과 기존 패턴의 의미 변경은 사용자 승인 전까지 표준으로 승격하지 않는다.

## 화면에서 보이는 구역

- **임시 생성**: 현재 PC의 로컬 인덱스. Git 제외, AI 영향 차단.
- **검토 대기**: Git에 보존된 사용자 검토 대상. AI 영향 차단.
- **승인 완료**: 정식 화면·패턴으로 승격된 자산. AI 표준 근거.
- **반려·보관**: 시행착오와 판단 기록. Git 보존, AI 영향 차단.

## 평가 항목

1. 생성 및 수정에 걸린 시간
2. 원본 업무 구조와 문구의 충실도
3. MES 표준 컴포넌트 재사용 여부
4. 임의 문구·임의 수치·임의 변형 발생 여부
5. 배치, 간격, 가로 스크롤과 반응형 안정성
6. 입력, 선택, 저장, 취소 등 실제 상호작용
7. 사용자 수정 지시 없이 첫 결과가 기준을 충족했는지
8. shell, content, behavior 패턴 선택과 실제 코드 조합이 일치하는지
9. 기존 패턴의 재사용·조합·확장·신규 제안·정규화 판단에 근거가 있는지
10. 기존 토큰과 컴포넌트를 사용하면서 미등록 wrapper나 정보 위계를 임의로 만들지 않았는지

## 패턴 판정 및 승인

화면과 패턴은 1:1 관계가 아니다. 하나의 생성 화면은 외곽 shell, 콘텐츠 구성, 상태 전이와 반복 행동 패턴을 여러 개 조합할 수 있다. AI는 코드 작성 전에 기존 후보와 차이를 비교하고 다음 중 하나를 선택한다.

| 판정 | 적용 기준 | 승인 |
|---|---|---|
| `reuse` | 검증된 패턴을 의미 변경 없이 재사용 | 자동 검증 가능 |
| `compose` | 기존 패턴 여러 개를 허용된 슬롯에서 조합 | 자동 검증 또는 저위험 검토 |
| `extend` | 기존 패턴의 적용 범위 안에서 variant·slot을 확장 | 사용자 승인 필요 |
| `propose-new` | 사용자 행동·상태 전이·정보 위계가 본질적으로 다름 | 사용자 승인 필요 |
| `normalize` | 근거 없는 단발성 시각 차이를 기존 표준으로 통일 | 판단 근거 기록 |

기존 패턴이 이미 같은 목적과 상태 모델을 담당한다고 선언했는데 새 요구를 표현하지 못한다면 새 패턴을 추가하기 전에 기존 패턴의 불완전성을 검토한다. 반대로 기존 패턴의 책임 범위 밖에 있는 새로운 행동 계약이면 신규 패턴 후보가 될 수 있다. AI는 이 차이를 제안하고 증거를 정리하지만 최종 승격 권한은 갖지 않는다.

승인되지 않은 조합은 실행 가능한 시안과 테스트를 가질 수 있지만, 후속 AI 생성의 표준 근거로 사용하지 않는다.

## 최초 기록

2026-08-11 이지모드 입고등록 생성안은 사용자 평가 50점의 `partial-success`다. 우측 슬라이드 구조와 컴포넌트 재사용·상호작용은 통과했지만, 원본에 없는 설명 문구 추가, 초기 팝업 유형·타이포 오판, 긴 소요 시간, 사전 자산 강제 실패 때문에 표준 승격을 보류한다.

## 개발자 전달 원칙

최종 전달물은 한 형식으로 통합하지 않고 역할에 따라 세 가지를 연결한다.

1. **Figma 승인 프레임**: 화면 구성, 문구, 상태와 시각 기준
2. **Git 코드**: 실제 컴포넌트 사용, 입력·선택·저장·취소 동작과 테스트
3. **접근 가능한 검토 페이지**: 후보 비교와 빠른 피드백. 사내 인증이 없으면 민감한 MES 화면을 공개 배포하지 않는다.

Figma만 전달하면 실제 React 상태와 테스트가 빠지고, 코드만 전달하면 디자이너가 승인한 시각 기준을 찾기 어렵다. 따라서 Figma 프레임과 코드의 화면 ID, 컴포넌트, 커밋을 서로 연결한다.

## Figma 가져오기 브리지

브라우저에서 React DOM을 복사해 Figma에 붙이는 방식은 편집 가능한 MES 컴포넌트 인스턴스를 보장하지 않는다. 다음 구조로 별도 브리지를 만든다.

1. 검토 페이지의 `Figma용 명세 복사` 버튼이 화면을 `ScreenSpec JSON`으로 클립보드에 복사한다.
2. 사내용 Figma 플러그인이 JSON을 읽는다.
3. 플러그인은 Figma Plugin API로 프레임을 만들고, 게시된 MES 라이브러리 컴포넌트를 key로 불러와 instance를 생성한다.
4. variant·text·boolean property를 ScreenSpec 값으로 설정한다.
5. 생성된 Figma 프레임에는 후보 ID와 Git 커밋을 기록한다.

SVG 복사는 빠른 이미지 참고용으로만 사용할 수 있고, 컴포넌트 연결과 편집 가능성을 잃으므로 공식 전달 방식으로 사용하지 않는다. Code Connect는 Figma 컴포넌트와 실제 React 컴포넌트를 Dev Mode에서 연결하는 용도로 사용하며, 전체 React 화면을 Figma 레이어로 역변환하는 도구로 해석하지 않는다.
