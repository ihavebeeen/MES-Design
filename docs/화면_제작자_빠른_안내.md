# MES 화면 제작자 빠른 안내

이 문서는 MES 디자인 시스템으로 신규 화면을 제작하는 사람을 위한 작업 순서다. 화면 제작자는 업무 요구사항과 결과 화면을 담당하고, 공통 컴포넌트와 패턴의 변경은 디자인 시스템 담당자와 협의한다.

## 1. 처음 시작할 때

저장소를 내려받은 뒤 `component-library` 폴더에서 실행한다.

```bash
npm ci
npm run dev
```

브라우저에서 [http://localhost:3000](http://localhost:3000)을 열면 컴포넌트, 패턴, 원본 화면과 생성 시안을 볼 수 있다. 이후에는 패키지 구성이 바뀌지 않았다면 `npm run dev`만 실행하면 된다.

## 2. AI에 전달할 내용

화면 형태를 먼저 지정하기보다 업무를 설명한다. 알고 있는 내용만 작성하고, 정해지지 않은 내용은 `미정`으로 남긴다.

```text
이 저장소의 .agents/skills/generate-mes-ui/SKILL.md를 사용해 화면을 제작해줘.

- 사용자:
- 업무 목적:
- 주요 정보:
- 판단을 돕는 보조 정보:
- 사용자가 해야 하는 행동:
- 반드시 지켜야 하는 조건:
- 참고할 Figma 또는 기존 화면:
- 아직 정해지지 않은 내용:

업무 의미를 먼저 정리하고 기존 MES 컴포넌트와 패턴의 선택 맥락을 확인해.
구현 후 로컬 미리보기, 코드 검사, 실제 화면 확인까지 진행해.
```

AI가 화면 구성에 영향을 주는 정보만 추가로 질문한다. 중앙 팝업, 우측 슬라이드, 테이블 선택 방식처럼 정해지지 않은 사항을 임의로 확정하지 않는다.

## 3. 결과 확인

로컬 미리보기에서 다음 항목을 확인한다.

| 확인 항목 | 확인 내용 |
|---|---|
| 업무 흐름 | 사용자가 필요한 정보를 찾고 작업을 끝낼 수 있는가 |
| 정보 위계 | 주요 정보와 보조 정보의 차이가 보이는가 |
| 화면 구조 | 메인 목록, 중앙 팝업, 우측 슬라이드의 선택 이유가 업무와 맞는가 |
| MES 일관성 | 공통 메뉴, 탭, 조회 영역, 테이블, 하단 액션이 기존 문법과 맞는가 |
| 상태와 동작 | 선택, 입력, 추가, 삭제, 취소, 저장이 화면에 반영되는가 |
| 화면 크기 | 잘림과 의도하지 않은 전체 화면 가로 스크롤이 없는가 |

수정이 필요하면 보이는 모양만 지시하기보다 업무상 이유를 함께 전달한다.

> 품목은 작업 대상을 식별하는 필수 정보이므로 첫 번째 열에 고정해줘. 다른 열의 너비를 조정하고 테이블 영역에서만 가로 스크롤을 허용해줘.

## 4. 화면을 저장소에 남길 때

처음 생성된 화면은 Git에서 제외되는 임시 미리보기에 저장된다. 검토 후 보관할 화면은 AI에 다음과 같이 요청한다.

> 이 시안을 저장소에 보관할 화면으로 전환하고, 변경 범위에 맞는 검사를 실행해줘. 공통 자산 변경과 화면 전용 변경을 구분해서 보고해줘.

일반 화면 변경은 다음 검사를 통과해야 한다.

```bash
npm run check:design-system
npm run verify:changed
```

공통 컴포넌트, 패턴, 맥락 계약을 변경했거나 배포 전 전체 확인이 필요하면 `npm run verify:full`을 실행한다. 검사 실패와 확인하지 못한 항목은 결과 보고에 그대로 남긴다.

## 5. 기존 자산으로 해결하기 어려울 때

화면 코드에서 비슷한 컴포넌트를 임의로 바꾸거나 공통 자산을 바로 수정하지 않는다. 아래 내용을 디자인 시스템 담당자에게 전달한다.

| 항목 | 작성 내용 |
|---|---|
| 필요한 역할 | 표현할 정보 또는 수행할 동작 |
| 가장 가까운 자산 | 확인한 컴포넌트·패턴 |
| 맞지 않는 이유 | 의미, 상태, 선택 방식, 배치 중 충돌하는 부분 |
| 사용 위치 | 화면과 영역 |
| 반복 가능성 | 다른 화면에서도 사용할 가능성 |

디자인 시스템 담당자는 기존 자산 사용, 화면 전용 조합, variant 확장, 신규 자산 후보 중 하나로 판정한다. 승인 전 신규 자산은 공통 컴포넌트로 배포하지 않는다.

## 작업 종료 기준

- 화면 제작 범위와 남은 항목이 구분되어 있다.
- 현재 코드에 연결된 검사 결과가 있다.
- 로컬에서 실제 화면과 핵심 동작을 확인했다.
- 공통 자산 변경 여부와 신규 자산 요청 여부가 기록되어 있다.
- 저장할 변경만 커밋되어 있다.
