# 실제 MES 웹과 Figma 대조 참고

## 왜 만들었나

현재 UI의 근거가 한곳에만 있지 않다.

- 최신 Figma가 디자인 원본이다.
- 같은 Figma 파일 안에 구형 화면과 후속 수정안이 함께 있다.
- 실제 웹에는 Figma에서 아직 찾지 못한 화면과 연결 동작이 있다.
- 실제 웹의 차이는 신규 요구 반영일 수도 있고 구현 오류일 수도 있다.

따라서 Figma 또는 실제 웹 중 하나를 통째로 정답 처리하지 않고, 실제 웹 메뉴마다 원본 후보의 위치와 미확인 상태를 따로 기록한다.

## 현재 기록한 범위

| 구분 | 수량 | 의미 |
|---|---:|---|
| 실제 웹 메뉴 | 42 | 현재 개발 MES에서 관찰한 메뉴 화면 |
| 최신 화면설계서에서 원본 위치 확인 | 38 | 최신 Figma 메뉴 그룹에서 대응 후보를 찾음 |
| 후속 수정 구역에서 원본 위치 확인 | 3 | 기본 메뉴 그룹이 아닌 후속 수정안에서 근거를 찾음 |
| 원본 위치 미확인 | 1 | KPI 화면은 명시적인 Figma 원본을 아직 찾지 못함 |
| 픽셀 검증 | 0 | 이번 배치에서는 위치만 연결했으며 시각 일치는 판정하지 않음 |
| Figma 기준 동작 검증 | 0 | 팝업 연결과 상태 전환의 원본 대조는 아직 하지 않음 |

기계 판독 원본은 `component-library/src/design-system/registry/web-figma-reconciliation.json`이다.

## 판단 순서

1. 최신 Figma의 `- 웹 화면설계서 (최종)` 페이지를 먼저 본다.
2. 같은 기능의 후속 수정 구역이 있으면 최신 변경 후보로 별도 대조한다.
3. 실제 웹은 화면의 존재, 진입 순서, 조건부 팝업과 상태를 확인하는 보조 근거로 쓴다.
4. Figma와 실제 웹이 다르면 어느 한쪽을 자동 채택하지 않는다.
5. 명칭, Shell, 배치, 상태, 동작 차이를 화면별로 판정한 뒤 표준에 반영한다.

구형 `MES v2.0` 페이지는 이력 참고용이다. 노드가 존재한다는 이유만으로 최신 원본으로 사용하지 않는다.

## 발견된 대표 충돌

- 실제 웹의 `판매계획관리(일)`과 Figma의 `판매목표관리(일)`은 명칭이 다르다.
- 생산계획 관련 Figma 하위 프레임 일부에도 `생산목표(일)` 표기가 섞여 있다.
- 운전일지는 실제 웹의 진입 경로에 따라 중앙 팝업과 우측 슬라이드가 다르게 관찰됐다.
- 생산실적과 입고등록은 중앙 선택 팝업 뒤 등록 슬라이드로 이어지는 연결 흐름이 있다.
- KPI는 실제 웹에 있으나 최신 Figma에서 대응 원본을 아직 찾지 못했다.

이 항목들은 오류라고 확정한 것이 아니라, 화면별 판정이 필요한 대조 대상이다.

## 비교할 때 주의할 점

Figma의 다수 `2700×1500` 프레임은 브라우저 화면 자체가 아니라 설명과 여백을 포함한 화면설계서다. 브라우저 viewport와 이 외곽 프레임을 직접 비교하면 크기 오차가 생긴다. 각 설계서 안의 실제 UI 프레임을 찾아 같은 viewport로 맞춘 뒤 비교해야 한다.

## 다음 작업

1. 한 번에 한 화면씩 실제 UI 프레임을 식별한다.
2. 외곽 크기와 배치, 토큰, 컴포넌트, 내용, 상태, 동작 순으로 대조한다.
3. 차이를 `구현 오류`, `Figma 원본 오류`, `의도적 예외`, `정규화 후보`, `근거 부족`으로 판정한다.
4. 판정된 내용만 ScreenSpec·사용 계약·시각 회귀 기준에 반영한다.
5. 아직 제공되지 않은 화면 유형은 실제 웹과 Figma에서 발견되는 순서대로 같은 장부에 추가한다.

현재 이 문서는 참고 대조 상태다. 원본과 완전히 동일하다고 검증된 화면 목록은 아니다.
