# Final implementation and preview delivery

## One managed route

`ScreenRequest → resolve → implement/generate → final-file audit → internal QA → screen:handoff → user URL`.

For `new`, inspect applicable MES components/pattern rules and interactions, not a matching whole-screen original or an aesthetic score. For `reproduce` / `normalize` / `audit`, also compare the original referenced by the contract. Captures are optional for discrepancies, uncertain measurements or requested evidence; copying baseline/final images every run is not required.

- `screen:generate --preview` and `mes_generate_screen` audit the generated bytes and the written file before creating internal QA. Without `--preview`, CLI generation still audits but produces code only, not a delivery pass.
- `screen:preview` audits handwritten TSX/JSX too. Alternate local source folders do not skip inspection. Managed preview routes stay under `src/app/preview/`, with realpath checks; standalone HTML/outside source paths are not accepted as previews.
- `screen:audit` / `mes_audit_screen` are read-only diagnostics, never delivery approval. Audit blockers set nonzero CLI exit / MCP `isError`.
- `screen:handoff` / `mes_handoff_screen` require a saved successful final-file audit, recheck current bytes, validate the exact preview wrapper and visual evidence, then return the delivery URL. No missing-result or exception fallback. MCP takes the same `request` and `sourcePath`; CLI takes contract/source file paths.

All paths below are relative to `component-library`. Run inside that directory:

```bash
npm run screen:preview -- .mes-ui-preview/<id>/contract.json src/generated-previews/<id>.tsx
# Actually confirm rendering and interactions at the contract viewport first.
npm run screen:handoff -- .mes-ui-preview/<id>/contract.json src/generated-previews/<id>.tsx --reviewed
# For original comparison, add --source-compared. Optional: --note "decision".
# Warning resolution: --warning "style.arbitrary-pixel=existing evidence reference"
# Unchanged render: omit --reviewed to reuse the observation.
```

Do not restart a server, open another route or generate temporary HTML to bypass a failure. If the repo must be read-only, first agree an allowed MES-based workspace/output approach; no arbitrary substitute.

## Short automatic records

Preview creation writes `implementation-audit.json`. After actual observation, handoff writes compact schema 2 `visual-review.json` with reviewer/time/viewport, rendered/interactions/sourceCompared flags and rendering/preview fingerprints. It does not generate a blank seven-item checklist. Existing schema 1 records remain readable and are not silently approved or rewritten. Do not create another MD or manually compute hashes.

`--reviewed` asserts actual rendering/interaction confirmation of the requested `verificationScope` at the contract viewport, not an automated browser test. `--source-compared` asserts the additional original comparison. Neither flag may precede observation. Missing/failed/unknown in-scope checks still block delivery. Parent integration outside surface scope is recorded automatically in `verification`, not added as a failed `unchecked` item or called verified. Only new decisions or warning resolutions need prose.

MCP `mes_handoff_screen` accepts the same request/sourcePath and optional `review: { reviewer, rendered, interactions, sourceCompared?, viewport?, note?, warningResolutions?, unchecked? }`. Supply truthful booleans after observation; omitted viewport uses the contract viewport. Failed/unknown observations invalidate earlier success. Omit `review` for re-delivery of the same version. `recordScreenReview` in `scripts/screen-handoff.mjs` also supports optional capture paths and hashes them automatically; recorded captures must still exist with matching bytes.

Audit fingerprints include registry/checker/config and implementation dependencies. Rendering fingerprints include the source path, transitive local code/styles/assets, layout/config/lockfile, contract and selected pattern records. A changed audit requires re-audit; identical rendering and wrapper can reuse observations. A later audit timestamp alone never invalidates comparison. Render/contract changes need affected checks again; new warnings need reasons. This does not rerender the entire catalog.

Confirm the requested surface's MES controls/styles/layout, cancellation/X/Escape, reopen and applicable save/input behavior, plus the displayed common frame. In connected-flow only, additionally exercise the relevant parent trigger, transfer/update and preserved search/selection/scroll. A missing business parent is not a blocker for surface: the labeled MES preview frame supplies chrome without inventing a list. A declared parent still participates in source checks/hashes because it is actually rendered. Report the returned verification scope; a surface pass is not an integration pass. Scope changes invalidate previous observations. Legacy checks still include displayed pageChrome.

## Enforcement boundary

| Program-enforced in managed commands | Agent/reviewer responsibility |
|---|---|
| Actual JSX/call bindings and exports; shared desktop chrome and selected shell; declared host or neutral preview-frame source and fingerprints; connected-flow requires a host | Choose scope from the user's task; inspect only relevant parent facts; do not narrow scope to evade errors; correct runtime host/trigger/data placement |
| Raw controls, custom screen CSS, HTML injection and unsupported dynamic rendering fail closed; explicit local boolean asChild API read from source permits false and a single literal-href anchor | Other slot/polymorphic as combinations need scoped checker support/tests, not a skip flag; unsupported does not mean inherently invalid design |
| Inline layout mechanics, stylesheet-defined tokens, passive roles and tabIndex=-1 allowed | Use actual MES variants for visual states; style/role suitability is not automatically proven |
| Registered DS internals can use native HTML; local helpers are inspected | Internal DS implementation quality remains covered by existing DS tests |
| Audit errors/blockers prevent new QA preview; missing/failed/stale observations prevent handoff | Genuine rendering/interaction confirmation and original comparison when relevant |
| Rehash current source, transitive local imports, styles, static local assets, app layout/config, lockfile, registry and checker; match exact wrapper and capture hashes | Remote data/assets, computed dynamic paths and runtime environment can change; inspect actual final render |

The AST checker is not a complete type checker or proof of runtime reachability: dead/hidden JSX, semantic misuse, all CSS utility overrides and fabricated evidence cannot be universally detected. Standalone CSS, dynamic styles/loading and polymorphic as remain unsupported; explain the constraint and agree a scoped alternative/support change. Run relevant compilation/browser tests, not a silent downgrade to pass.

This is a **command-time delivery gate**, not a live web-server firewall. Existing/manually authored preview routes, arbitrary external servers, direct `next dev`, a manually pasted URL, edited checker/receipts, and changes after handoff remain possible. Existing catalog records are historical drafts, not proof of current validation; new QA previews are no longer auto-added. A previously delivered live URL can change; rerun handoff before delivering revisions. Repeated hashing is limited to the current screen graph, not rerendering the whole asset catalog.
