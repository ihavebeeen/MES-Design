# Final implementation and preview delivery

## One managed route

`ScreenRequest → resolve → implement/generate → final-file audit → internal QA render → baseline comparison → screen:handoff → user URL`.

- `screen:generate --preview` and `mes_generate_screen` audit the generated bytes and the written file before creating internal QA. Without `--preview`, CLI generation still audits but produces code only, not a delivery pass.
- `screen:preview` audits handwritten TSX/JSX too. Alternate local source folders do not skip inspection. Managed preview routes stay under `src/app/preview/`, with realpath checks; standalone HTML/outside source paths are not accepted as previews.
- `screen:audit` / `mes_audit_screen` are read-only diagnostics, never delivery approval. Audit blockers set nonzero CLI exit / MCP `isError`.
- `screen:handoff` / `mes_handoff_screen` require a saved successful final-file audit, recheck current bytes, validate the exact preview wrapper and visual evidence, then return the delivery URL. No missing-result or exception fallback. MCP takes the same `request` and `sourcePath`; CLI takes contract/source file paths.

All paths below are relative to `component-library`. Run inside that directory:

```bash
npm run screen:preview -- .mes-ui-preview/<id>/contract.json src/generated-previews/<id>.tsx
# Internal QA only: use the browser at the reported QA URL and compare with the baseline.
# Complete .mes-ui-preview/<id>/visual-review.json using actual observations.
npm run screen:handoff -- .mes-ui-preview/<id>/contract.json src/generated-previews/<id>.tsx
```

Do not restart a server, open another route or generate temporary HTML to bypass a failure. If the repo must be read-only, first agree an allowed MES-based workspace/output approach; no arbitrary substitute.

## Evidence format

Preview creation writes `implementation-audit.json` and an **unfilled** `visual-review.json`. The latter is not auto-approved. Preserve the supplied implementation/preview fingerprints; after changes, reread the fresh audit and actually repeat affected checks before updating them. Old visual records are not overwritten automatically.

Complete:

- `reviewer`, `comparedAt` (ISO timestamp after the latest audit), `viewport.width/height`.
- `baseline.kind`: `figma`, `approved-mes`, or `user-approved`; `reference`: exact node, registered screen/state or explicit scoped approval. New screens can compare reused areas with multiple approved MES references; a new original Figma screen is not mandatory.
- `baseline.artifacts` and `renderedArtifacts`: arrays of `{ "path": "reference.png", "sha256": "..." }`, paths relative to the review JSON or absolute. Use real PNG/JPEG/WebP captures for relevant states. The gate checks file existence, image signature and byte hash, not visual correctness. Obtain SHA-256 with Node crypto or `Get-FileHash`.
- `checks`: `shell`, `pageChrome`, `dateInput`, `spacing`, `colorFontRadius`, `layoutHierarchy`, `interactions`. Each needs `{ "status": "passed", "note": "specific comparison / measurement / behavior result" }`. Initially all are `not-checked`. `failed`/`not-checked` blocks. Only absent date controls and overlay page chrome allow `not-applicable` with a reason; do not mark a used date control N/A.
- `warningResolutions`: each static warning needs `{ "code": "style.arbitrary-pixel", "reason": "measured baseline / approved normalization" }` when applicable. This cannot waive blockers.
- `unchecked`: must be empty for handoff. If something remains unknown, report the blocker rather than writing a false pass.

For visual checks compare common navigation/tabs, actual MES date API, spacing, colors, font family/size/weight, radius, section title hierarchy, density and alignment. For interactions exercise inputs/selection/cancel/X, check console errors and unintended overflow. Include visible states in captures. Report automated checks, visual observations and unverified limits separately.

## Enforcement boundary

| Program-enforced in managed commands | Agent/reviewer responsibility |
|---|---|
| Actual JSX/call import binding; exported MES symbol, not names/comments; contract shell/sections/actions | Correct choice for meaning, hierarchy and business context |
| Raw controls, custom CSS/inline styles, HTML injection and unsupported dynamic rendering in screen/helper code fail closed | Approved new semantics: update supported contract/checker with tests, not a skip flag |
| Registered DS internals can use native HTML; local helpers are inspected | Internal DS implementation quality remains covered by existing DS tests |
| Audit errors/blockers prevent new QA preview; unfilled/failed evidence prevents handoff | Genuine baseline selection and visual/interaction comparison |
| Rehash current source, transitive local imports, styles, static local assets, app layout/config, lockfile, registry and checker; match exact wrapper and capture hashes | Remote data/assets, computed dynamic paths and runtime environment can change; inspect actual final render |

The AST checker is not a complete type checker or proof of runtime reachability: dead/hidden JSX, semantic misuse of a valid component, all CSS utility overrides and fabricated evidence cannot be universally detected. Run relevant compilation/browser tests. It conservatively blocks unsupported screen CSS, render overrides and dynamic loading; approved alternatives require extending its support, not silently downgrading the result.

This is a **command-time delivery gate**, not a live web-server firewall. Existing/manually authored preview routes, arbitrary external servers, direct `next dev`, a manually pasted URL, edited checker/receipts, and changes after handoff remain possible. Existing catalog records are historical drafts, not proof of current validation; new QA previews are no longer auto-added. A previously delivered live URL can change; rerun handoff before delivering revisions. Repeated hashing is limited to the current screen graph, not rerendering the whole asset catalog.
